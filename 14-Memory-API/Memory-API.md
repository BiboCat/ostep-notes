#### 零、内存API

本章没有继续展开内存虚拟化的内容，而是**从内存虚拟化的结果出发**：**进程拿到了自己的地址空间，能够有什么方式管理自己的内存**？

进程API是内核对进程开放的接口，用于给进程"请内核办事"，办的事情是有关于进程的，如`fork`等；内存API是内存对进程开放的接口，它们一般用来操作堆`heap`，它们和内核无关，不是系统调用，是库函数。

**CRUX：HOW TO ALLOCATE AND MANAGE MEMORY**——（程序）如何分配和管理内存？

#### 一、两类内存

上一章地址空间的学习中，我们得知地址空间中有两类内存：栈`stack`和堆`heap`。

栈内存：

- 存局部变量、函数参数，管理函数调用链等。

- 分配与释放由编译器隐式完成；比如C语言编写代码时，只需要声明函数并直接调用即可，不需要手动管理内存，编译器会帮你腾出空间、释放空间。

堆内存：

- 所有分配和释放都由代码显示处理。

其实这一小节（14.1）的内容就和C语言差不多。书上的举例就不过多讨论了。由于只有堆内存是显式调用、人为管理的，因此**下面的内存API都是属于堆内存的**。——后面也和C语言差不多！

#### 二、malloc()

语义：传递一个大小`size`（单位是字节），向堆索要空间。如果成功，返回新空间的指针；如果失败，返回`NULL`。

```c
#include <stdlib.h>
...
void *malloc(size_t size);
```

- 要用 `malloc` 只需 include `stdlib.h`。

- 但原文紧接着说：**其实你连这个都不必做**——所有 C 程序默认链接的 C 库里面就有 `malloc()` 的代码；**加头文件只是让编译器能检查你调用得对不对**（参数个数、类型）。

随后作者讲解了关于`sizeof()`的知识。它不是一个函数，而是一个运算符，它会在编译的时候计算出结果，把结果数字放进去，而非作为函数（没有调用栈）。叫"编译期运算符"。

*后续关于`sizeof()`的要点，我不做讨论，这更多属于C语言的内容！*

#### 三、free()

语义：传递一个堆上的指针，将这一块被占用的内存释放掉。

提出一个问题，`free()`只获得了一个指针，它是如何知道这块内存空间有多大的呢？

这涉及内存空间`chunk`的话题。

---

##### malloc内存分配——chunk

64位`glibc`中，每一个`malloc`的内存空间，都以`chunk`的形式存在。它的规则如下：

- `chunk`的大小必须为16字节的整数倍，保证地址16字节对齐。

- `chunk`头部共16字节，包括8字节的`prev_size`，和接着的8字节的`size`。

- `chunk`头部后接着真正的内存空间；且内存空间有最小大小：16字节。

- `malloc`返回的指针指向真正的内存空间的起始地址。

把上述规则化成一张图如下：

```
 低地址
 ┌─────────────────────────────┐
 │  prev_size   (8 bytes)      │
 ├─────────────────────────────┤
 │  size        (8 bytes)      │
 ├─────────────────────────────┤ ← malloc() 返回的指针正好指这里
 │  user data                  │ 最小大小16字节，malloc(1)也给你16字节的数据空间
 │  ...                        │
 ├─────────────────────────────┤
 │  next chunk - prev_size     │
 ├─────────────────────────────┤
 │  next chunk - size          │
 └─────────────────────────────┘
 高地址
```

现在咱看看`size`和`prev_size`都有什么作用。

`size`：
存这个`chunk` 的**总大小**，包括头部16字节；
由于`chunk`大小为16的倍数，因此`size`的低4字节全为0；
秉承着不浪费的原则，`size`低3字节留给了三个标志位：`PREV_INUSE`、`IS_MMAPPED`、`NON_MAIN_ARENA`。因此读取大小的方法是`size & ~0x7`。

`prev_size`：
存**上一个**`chunk`的总大小；
它用于给`free`命令**合并**空闲堆内存空间——这个在原书17章展开。

<u>虽然还有疑问</u>，但到这里就能解答`free()`是如何知道内存空间有多大的了：指针往前（低地址方向）16字节，就有这个`chunk`的大小。

#### 四、Common Errors

这一节14.4，作者讲了一些关于内存分配和管理的常见错误。这也属于C语言内容，我们过一过。

- 忘记分配（野指针）

- 分配不够：`strlen()`返回字符串字符数量，忽略实际保存下的最后的`\0`符号

- 忘记初始化：只分配了内存，没对这块内存做赋值就使用其内容，这是无意义的

- 内存泄露：用完忘记释放

- 提前释放：还没用完就释放

- 重复释放

- 错误释放：释放错空间了

这些都是一些逻辑问题，编程时注意一下就可以了，不过多赘述和展开。

#### 五、补充

本文还讲述了其他的内存API，比如熟悉的`calloc()`、`realloc()`（14.6小节）。

- `calloc()`：分配内存，**并在返回前清零**。等于是自动初始化内存空间，全部写成0；

- `realloc()`：对于一块已分配的内存使用，为它分配更大的空间，同时原有内容拷贝到新内存空间中。先后的内存空间地址不一样，函数返回新空间的指针。

在14.5小节，作者则补充说明了这些库函数（内存API）与系统调用的关系。

**诸如`malloc()`的这些库函数，本身不是系统调用，是在内存自己的虚拟地址空间中管理。**但是不代表没有和内存管理有关的系统调用（不属于内存API的概念），作者举例了几个有关内存的系统调用，简单过一下，这并非重点：

- `brk`：用于改变程序的**`break`**位置——即**堆的末尾**。它接收一个参数（**新`break`的地址**），于是根据新`break`比当前`break`大还是小，**扩大或缩小堆**。

- `sbrk`：作用类似`brk`，但是传递的参数是增量。
