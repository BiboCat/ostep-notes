#### 零、内存虚拟化

回顾上一章的内容，CPU虚拟化让一个CPU同时跑多个进程，每个进程都以为自己有CPU用；内存虚拟化同理，让一块内存上同时存多个进程的内容，每个进程都认为自己有一块完整的内存。

上一章中我们曾扩展学习了关于进程内存空间的问题，进程认为自己的那一块内存，是从0地址开始的。并且除了进程自己的内容外，内存高地址还会存关于内核的内容（内核代码、内核全局数据、所有内核栈）。

做到内核内容的复用，使得每块地址空间从0开始，这就是内存虚拟化所解决的问题。

#### 一、动机

本章13.1和13.2小节简单说明了为什么需要内存虚拟化，我们简要带过：

- 多个程序同时运行的需求

- 切换进程不能对整个内存保护和切换（开销太大），各进程的内容数据必须同时存在于内存中

- 以及刚刚说的，内核内容的复用等

#### 二、地址空间

地址空间，就是运行中的程序所看到的内存视图。包含进程所需的全部内容，**它是内存虚拟化的结果**。

`Figure 13.3`是一个地址空间的例子（未包含内核空间，这是一个简单的例子）。

```
        0KB  ┌───────────────────────────────┐
             │          Program Code         │ ← 代码段 code segment
        1KB  ├───────────────────────────────┤
             │            Heap               │ ← 堆 heap
             │              │                │
             │              │  (it grows     │
             │              ▼  positively)   │  堆向高地址增长
        2KB  ├───────────────────────────────┤
             │                               │
             │           (free)              │
             │                               │
             │              ▲  (it grows     │
             │              │  negatively)   │
             │              │                │  栈向低地址增长
       15KB  ├───────────────────────────────┤
             │            Stack              │ ← 栈 stack
             │                               │
       16KB  └───────────────────────────────┘
```

简单说明一下：

- 地址空间从0开始

- 0地址开始存代码段`code segment`用于存放程序指令

- 代码段后接着堆`heap`，和C语言中学过的堆含义相同，存放如`malloc()`来的数据

- 栈`stack`从最高地址往低地址增长，存放如局部变量、函数调用链、参数等

所以，这是内存虚拟化的产物，咱们先建立认知，不深究它的由来。

*另外，作者对这个例子有一个脚注，那就是`heap`和`stack`对着生长的办法在多线程下失效——可是本书有关线程的部分，在很后面才讲，现在咱们从简单模型开始，先忽略！*

#### 三、目标

本章的重点——地址空间，已经讲完了。13.4小节，坐在这讲述了内存虚拟化的三个目标：

- 透明性：虚拟化对程序不可见，程序认为自己独占私有物理内存。

- 效率：时间上，虚拟化不能让进程使用内存时耗费过多的时间；空间上，不能让管理结构使用太多内存。

- 保护：进程的`load`、`store`、取值等不能触碰其他进程或OS的内存。

#### 四、总结

**本章重点是介绍地址空间的概念**，就是内存虚拟化的结果。另外介绍了内存虚拟化的动机和目标。——这些都不需要特别去记忆，有个大概的概念即可，后续会慢慢理解。

特别是，"上面说进程不能触碰其他进程和OS的内存"，和之前说的内核代码映射到地址空间高地址部分看似有矛盾，但实际上二者同时存在："不能触碰是在低权限下不能触碰"。
