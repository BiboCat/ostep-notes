#### 零、从分段到分页

第十六章介绍了分段的机制，它的一个毛病是：外部碎片越用越多，难以管理。由此，这章引入并介绍了分页的机制。

分段是变长的切分，而分页是定长的切分。物理内存又被划分为了一块一块的空间，管理起来更简单——但是如何解决定长物理内存的内部空洞问题？让地址空间可以稀疏使用？

看来分页将会有很多机制等待学习，让我们往下看！

#### 一、基本机制

分页机制把地址空间和物理内存都划分为固定长度页的组合。
比如一个页被设定为16字节，那么64字节的地址空间就有4个页；128字节的物理内存就有8个页。

- 地址空间中划分的页称为**虚拟页`VP`**，用虚拟页号(`VPN`)记作`VP0 VP1 ...`；
  同理物理内存中划分的页称为**物理页**，又称**物理帧`PF`**，记作`PF0 PF1 PF2 ...`。
  虚拟页和物理页的大小相同。

- 虚拟页被打散放到任意空闲帧中，比如`VP0 -> PF3`、`VP1 -> PF6`。

- 虚拟地址高位做`VPN`，低位做页内偏移`offset`；物理地址相同，高位是物理页号，低位是页内偏移。（低位位数由页大小而定）

- 页表`page table`，是**每一个进程独立一个**的数据结构，记录`VPN -> PFN`的映射。

- 由于页大小相同，因此地址转换时只需要映射`VP -> PF`即可！
  
  - `VA = VPN || offset`，取出`VPN`部分
  
  - 查页表`VPN -> PFN`
  
  - 拼成：`PA = PFN || offset`

```
       虚拟地址空间               页  表                   物理内存
       (每进程一份)            (每进程一份)               (全系统一份)
         4 页               VPN  ──►  PFN                 8 帧

       +--------+          +----------------+          +--------+
       |  VP0   |          |  0  ──►  PF3   |          |  PF0   |  空闲
       +--------+          +----------------+          +--------+
       |  VP1   |          |  1  ──►  PF6   |          |  PF1   |  VP2
       +--------+          +----------------+          +--------+
       |  VP2   |          |  2  ──►  PF1   |          |  PF2   |  空闲
       +--------+          +----------------+          +--------+
       |  VP3   |          |  3  ──►  PF5   |          |  PF3   |  VP0
       +--------+          +----------------+          +--------+
                                                       |  PF4   |  空闲
              页表就一块"跳线板"：                        |  PF5   |  VP3
              把 VP 的编号重新接到 PF 的编号上             |  PF6   |  VP1
              两边的编号毫无关系                          |  PF7   |  空闲
          
 
        虚拟地址 VA :    +-----------------+------------------+
                        |   VPN  (高位)   |   offset (低位)   |
                        +-----------------+------------------+
                                 |                    |
                                 | 页表映射            |  原样照抄
                                 |                    |  (不改一个 bit)
        物理地址 PA :    +-----------------+------------------+
                        |   PFN  (高位)   |   offset (低位)   |
                        +-----------------+------------------+
```

#### 二、页表

###### 页表存储位置——内存中

18.2小节，作者从页表的大小入手，说明了页表不能存在硬件中，要存在内存中。

以32位的地址空间，和4KB大小的分页举例（`x86`）：地址由20位`VPN`和12位的`offset`组成。而20位的`VPN`，最多有**`2^20`**条映射，这显然在硬件中存不下来。

因此，页表只能放在物理内存中。**硬件中有一个专门的寄存器`PTBR`(page-table base register)指向当前进程的页表的起始物理地址。它也是进程切换中的重要值，是PCB中的一项。**

###### 页表的组织形式

页表以**页表项(Page Table Entry `PTE`)**作为单位，它是一条`VPN -> PFN`的映射记录。

最简单的页表——**线性页表，是一个`PTE`的数组，数组的下标就是`VPN`**；

至于`PTE`的内容，以`x86`的32位`PTE`为例（物理内存4GB、页4KB），下表给出（参考原文`Figure 18.5`）：

| 位     | 字段                        | 作用                                             |
| ----- | ------------------------- | ---------------------------------------------- |
| 31–12 | **PFN**（物理帧号）             | 这页在物理内存的第几帧；**20 位**，因为 4KB 页下 4GB/4KB = 2²⁰ 帧 |
| 11–9  | 保留 / available            | OS 自用                                          |
| 8     | G（global）                 | 全局页，切换进程时不必刷新 TLB                              |
| 7     | PAT / PS                  | 页属性 / 大页标志                                     |
| 6     | **D**（dirty）              | 调入后是否被写过 → 换出时要不要写回磁盘                          |
| 5     | **A**（accessed/reference） | 是否被访问过 → 页替换时判断「热不热」                           |
| 4, 3  | PCD, PWT                  | 缓存策略                                           |
| 2     | **U/S**（user/supervisor）  | 用户态能否访问                                        |
| 1     | **R/W**                   | 可读还是可写                                         |
| 0     | **P**（present）            | 在不在物理内存                                        |

除了页表的核心功能（页号转换）外，`PTE`中还拥有许多标志位：

- 存在与有效：`P`  ；存在才能用，否则交给内核判断

- 保护与权限：`R/W`、`U/S`  ；便于共享物理内存

- 缓存策略：`G`、`PAT`、`PCD`、`PWT`  ；用于更复杂的页表管理策略

- 记录：`D`、`A`  ；用于更高级的页表管理策略

*这些标志位，在本章仅仅要求了解，因为基于它们的更复杂的机制和策略，本章暂未展开！*

#### 三、页表的开销

18.4小节，作者讨论"**页表为什么慢？**"

刚刚我们推断出，页表只能放在物理内存中。也就是说，**当我们想要访存时，就得先查页表**——而读一次页表的`PTE`也是一次访存，**这样每次访存都得访问两次内存**。这是**时间开销**。

同时，页表的**空间开销**也不小。`x86`的`VPN/PFN`有20位，因此页表项最多有`2^20`条；一条`PTE`是4字节，因此页表最多要占用`400MB`内存。

这些现有缺点是当前简单页表模型中的，这正是页表需要改进的地方，新机制将会在后续章节展开。

18.5小节，作者以一个程序例子，**量化分析了页表的开销**。

```
1024 movl $0x0,(%edi,%eax,4)
1028 incl %eax
1032 cmpl $0x03e8,%eax
1036 jne 1024
```

以上是举例程序，这是一个循环程序，只看一轮循环：
`movl $0x0,(%edi,%eax,4)`：<u>取一次指令</u>，<u>写立即数0</u>
`incl %eax`：<u>取一次指令</u>，`eax`自增
`cmpl $0x03e8,%eax`：<u>取一次指令</u>，立即数1000与`eax`比较
`jne 1024`：<u>取一次指令</u>，根据标志位更新`PC`寄存器的值

其中划线的操作，是需要访问内存的，一共访存五次；而每次访存，都需要查页表——因此一轮循环总共访存10次。

| 访存类型    | 次数     | 说明                      |
| ------- | ------ | ----------------------- |
| 取指      | 4      | 4 条指令，每条都要翻译            |
| 显式写数组   | 1      | `movl $0,(%edi,%eax,4)` |
| **查页表** | **5**  | 上面 5 次访问各配一次            |
| 合计      | **10** |                         |

问题有两个：
①访问一次内存，必须访存两次
②上述4次取指，**一直访问同一页，做了4次相同的映射**（相邻的指令大概率在同一页）

*特别是②，就是后续章节解决的核心问题。*
